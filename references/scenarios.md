# 场景规则

## 研究实验与模型资料

- 初稿、修订和探索按实际用途区分，沿用当前实验计划编号。多个模型可以按模型→数据集组织，自有模型与对照资产的范围由用户决定。
- 每个采用运行应关联输入、代码版本、训练参数、聚类参数、种子、最终权重、embedding／预测及指标；已有元数据足够时不重复生成新格式。
- 多种子保留每个采用种子的必要资料；不能仅留最佳种子权重却保留多种子均值。
- 指标对应同一批预测和有效样本掩码；区分类别数、聚类协议、开发／验证与均值／最佳单次，不为精简将不同结果合并成一个“最佳”。
- 缺原始记录时列缺口，不默认重训，不以其他实验替代。整理不扩大实验承诺。
- 先确定失败类型及处置对象：负结果保留结论和限定；环境/输入错误保留可诊断记录；下载中断先查是否仍在恢复；已替代的调试代码查调用闭包后退役。不能把它们统一命名“失败文件”批量处理。
- 不因指标低或对模型不利删除证据。弃用与失败资产同样受信息守恒约束：仅在信息已完整保留且有清理授权时删除。直接支撑审稿问题、限制和当前结论的结果不得被隐去。
- 保护唯一输入、检查点和不可重建预测；日志是否可删取决于是否包含独有配置、故障或训练信息。

## 源代码与版本仓库

- 先核对工作区、分支与调用关系；本地历史删除记录不等于需要上传的代码变更。
- 入口／模块重命名检查导入、命令、配置和脚本，不因名称相同就认定实现重复。维护入口、实际默认测试与生成器的调用是当前依赖；历史文档提及、已关闭研究的重放依赖和仅为登记而检查存在性分别处理。已关闭实现可保留精确可恢复源码后退役；保留历史身份和恢复方法，不改冻结哈希。
- 根目录生成物须辨明实物：`.build`也可能含唯一源稿，`tmp`也可能含唯一结果，`egg-info`可能影响安装元数据。分类归位、移除或重建前检查当前消费者与替代位置，移除后验证命令入口和安装元数据仍可解析。
- 数据、权重、缓存与凭据不随代码整理进入远端。发布另需授权，提交范围最小；核查作者身份，不伪造贡献者或重写他人历史。
- Git 索引和历史不是普通缓存；不为省空间直接删除。用户要求历史时备份历史，仅备份工作副本时明确范围。

## 文档、图表与交付

- 整理目录不默认修改 DOCX/PPTX/PDF 内容；保留明确要求不动的文件。
- 区分可编辑源文件、最终交付与可再生渲染产物，不能删除唯一源数据后只留截图。
- 用户另需内容或版式优化时使用相应文档流程；不得悄悄移除结论依据中的不利结果。

## 压缩与备份

- 核对目标容量、文件系统限制和源文件变化。备份只复制，不隐含删源。
- 选择无损压缩，已有压缩格式先估算收益。不通过降精度、删张量或重编码实现所谓无损。
- 按用途建立少量压缩包，明确共同恢复根目录，大包使用支持大文件的格式。优先使用环境已有的兼容工具。
- 临时包使用 .partial 等后缀。逐条检查成员、解压可读性、CRC 与解压内容 SHA256，匹配稳定源文件；记录整包 SHA256 后才改为正式名称。
- 检查读取前后源文件状态，变动文件重验。失败不能直接标成功；恢复中断时先确认源与压缩包未变再复用已校验成员。
- 大文件流式处理，内存紧张减小缓冲，不整包／整权重读入。耗时任务可暂存恢复进度，完成后仅删除无独有信息的进度副本；必要恢复与溯源信息保留到正式清单。
- 最终通常只需压缩包、恢复说明与校验清单；复现需要时再保留环境、代码版本和复验脚本。整理目录后修复复验脚本路径。
- 已校验包同卷移动不必重复全量解压；检查位置与大小，有新变化再扩大验证。大小明确使用字节、GB 或 GiB。

## 下载与个人文件

- .partial、.crdownload 等先核对所属应用和下载状态，不能凭后缀删除；无法确认则保留并指出。
- 按用途分类，必要时细分日期和项目；不以扩展名分类打散项目关系。
- 照片、音乐和应用资料库可能依赖目录或数据库，先辨明原始文件、导出件及软件管理边界。
