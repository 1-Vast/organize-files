# 科研代码与滚动报告治理

## 代码：先确定职责，再决定改写或退役

| 类别 | 处理及验证 |
|---|---|
| 现役实现 | 查真实调用和瓶颈；有依据才合并重复逻辑或优化，固定输入验证输出及必要接口 |
| 关闭/失败研究实现 | 保留准确代码版本、参数、结论、失败原因和必要运行资产；无现役依赖后集中退役 |
| 调试/迁移/过时生成器 | 查独有信息、动态调用和输出位置；完整被替代后清理，防止再次生成旧树或覆盖维护报告 |

静态分析仅产生候选：未使用导入可能注册插件/触发副作用，重复语法不保证算法等价；测试、动态导入、配置、CLI和运行登记共同判定现役范围。可用已有Ruff等工具，但不为普通整理新增工具链，不批量应用不安全修复。

先测再改：在同环境、同输入、同缓存/重复条件下测时间、内存或I/O，说明计时边界和样本规模。用最小补丁修证实的瓶颈；不为了减少行数改算法，不优化未观测到的理论问题。科研代码尤其保护随机种子及随机数消耗顺序、切分/掩码、排序与并列规则、dtype/精度、单位、容差及输出格式。浮点优化须事先声明可接受误差，不能看到差异后放宽。冻结实验实现原字节不动，必要时优化维护副本并明确新版本，未复核时不得替换科学依据。

失败方法的科学证据与所有开发过程脚本不等价：保全解释结论和重放必要比较的精确实现、配置和独有失败记录，冗余尝试按覆盖与依赖闭包集中退役；不能按低分删除不利证据。软件测试通过不证明方法已验证有效。

## 报告：现行入口、权威章节、精确来源

沿用现有入口和按问题维护的详细报告，不强制单一巨型报告或固定数量。只有问题实质分化、当前使用确有收益时才拆分；拆分必须修引用，不复制同一长段。来源层保留运行、原文、修订及冻结版本，以稳定身份引用，不把全部原文反复嵌入现行报告。

每次更新先判断：

1. 同问题是否已有权威报告/章节？有则使用它，无变化保持字节和mtime，不新建FINAL_v2或整理总结。
2. 新证据是否改变数值、解释、限制、证据等级、使用状态或既有下一步？只更新实际受影响章节及当前消费者；元数据变化只触发复核，不自动翻转结论。
3. 更正能否定位原说法、原始依据和现行解释？避免只引用上一轮摘要造成摘要的摘要；删除前用独有事实/条件/限制覆盖表核对原文。
4. 旧散稿是否完整被替代，引用已更新，精确恢复源真能读取？通过才按既有授权清理。
5. 是否论文/预注册/正式验证/交付冻结节点？保存必要固定版本及身份，不持续覆盖冻结内容。现行报告标记之后的修订关系。

增量扫描仅减少候选筛选成本。大小/mtime甚至ctime相同不证明字节相同；Git变更也不能覆盖未跟踪/忽略数据。准备删除、替换、冻结绑定验证或声明完整性时仍须严格哈希，保留执行前并发变化检查。已验证大包无新变化且不再次破坏其来源时可复用既有校验，不为重复整理全量解压。读取范围、实际哈希字节和次数分开记录；无法取得真实模型Token则N/A。

## 重要结论的证据契约

复用登记和来源索引的现有字段；按重要结论补齐以下关系，无资料则明确缺失，不制造新模板或把每个文件变成节点：

| 维度 | 必须可追问的身份 |
|---|---|
| 研究 | 问题、假设、实验/运行、采用或弃用依据 |
| 数据 | 版本/哈希、样本集合、切分、暴露情况与有效掩码 |
| 方法 | 代码版本/内容身份、参数/种子、生成与评价入口、必要环境 |
| 结果 | 数值/单位、统计对象、误差/区间、纳入集合、强基线与预算 |
| 证据等级及边界 | 探索/验证/独立确认/间接证据，适用条件、未执行和缺口 |
| 修订 | 支持、反驳、收窄、更正、取代与受影响决定 |

分开验收：**完整性**是独有事实和精确资产可取得；**真实性**是陈述与对应输入/协议/计算吻合；**适用有效性**是证据等级、当前状态和可推广范围没有被扩大。可读哈希/链接/关系图主要验证前者，不替代后两者。负结果、工程失败、未执行和未知必须分别保留；独立审查按具体来源与条件给结果，不以另一个agent自称通过作证明。

## 发布与接续

用户要求上传整理成果时，先将本地改动、Git已跟踪历史、忽略规则和远端实际内容对应起来，按既有授权核对发布差异。不能把所有既存删除都当成错误，也不能用全量暂存把封存副本、数据和环境带入远端。关键来源优先复用已有版本；无须为本地大包复制一套平台或强制引入LFS。

核查代表性结论及登记研究的协议、实现、配置、更正和失败依据在接收环境中能否取得。固定Git提交与blob可保留已入库来源身份，但Git规范化文本与本地原始字节可能不同，须分别记录身份与校验口径；未入库的关键文本需要补充，数据/保护资产明确为外部依赖。路径清单、hash或本地包存在不能冒充远端已具备来源。

用外部干净检出验证拟提交树，避免本地未跟踪或忽略文件掩盖缺失依赖。默认软件回归使用合成输入及可取得的关键文本；真实数据/大包核验另列为显式集成检查，启用后缺资产必须失败。不能删除行为测试、无条件跳过来源检查或把元数据校验改名为内容验证来获得绿灯。浅克隆的固定历史来源须有明确获取办法，CI按需配置历史深度。

最终分别报告本地整理、远端发布和数据级复现的状态；远端SHA、范围及适用CI通过后才称发布完成。未上传数据时不声称完整实验可立即重跑，也不因数据未上传否定已完成的关键信息交接。将实测暴露的通用问题回写skill既有章节，不为每次案例再建永久总结。

可借鉴[FAIR](https://doi.org/10.1038/sdata.2016.18)的可发现/访问/互操作/复用、[FAIR4RS](https://doi.org/10.1038/s41597-022-01710-x)的软件版本/身份/依赖，以及[RO-Crate](https://www.researchobject.org/ro-crate/technical_overview)的轻量研究对象关系。它们是设计参考，不表示通过认证；不强制改造格式或声称采用某未核实规范版本。

## 研究决策继承与来源复核（按重要性启用）

在现有结论/决策对象中记录适用范围、真实对照、否定证据、原始决策理由、重启条件和对应 source_ids；不建立第二套决策数据库。不要把工程失败误记为科学方法失败，也不要因为已有停止决定而禁止新背景下的独立检验。变更范围或证据等级时，定位源协议和修订记录并核对，而不是凭 status 字符串自动升级。

保留来源ID和已验证来源必须区分：evidence_index 对 source_ids 不读取 payload，默认标记为未验证及其依赖需复核。项目拥有可信且可访问的保留记录读取器时，另行读取并核验源字节/固定 Git 表示，并记录核验身份与范围；仅有来源 ID、哈希字段或本地路径不能宣称已经核验。严禁未经认证把未验证来源从影响传播中排除。

拟删除的独有文本先按事实单元建立最小覆盖映射：数值及精度、实验条件、对照、否定结果、未完成状态、更正与适用边界；逐项定位保留报告的准确位置。对于证据升级、条件消失、数值改变和负结果消失，需独立追溯原始证据。源记录能恢复不等于综合报告已经覆盖全部独有事实；不能证实覆盖则保留源件。

## 索引导航一致性（轻量检查）

当研究索引含 study 与 thematic_report、正文以明确研究ID组织时，可使用 `scripts/research_navigation.py` 核对目标章节是否包含研究ID；它只产生待复核候选，不自动改科研结论或重定向。对于跨章节研究、文本别名或未标明ID的条目，应由 agent 阅读内容确认主章节；链接存在性不能证明语义导航正确。只在索引或报告改变时执行，不为所有资料构建新关系库。
