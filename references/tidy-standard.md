# 整齐与命名标准

深度重构，或用户要求“整齐、美观、规范命名、强迫症级整理”时使用。目标是让每一层一眼可懂、同级排列有序、没有一件说不出用途的东西。科学内容与证据规则仍以 [SKILL.md](../SKILL.md) 为准；本标准只决定形状和名字。

## 1. 结构

- **每层一个分类轴。** 同一层只按一种依据分（用途、阶段、主题或数据集），不混用；不按文件格式建 `docx/`、`png/`、`pdf/`，除非整层本来就是单一格式的交付物。
- **根目录只放入口。** README、主程序或配置等约定入口加少数用途目录；其余散件（一般超过 5 个即算）归入用途目录。
- **层级与数量相称。** 每个目录宜 3–15 项；只装一个子目录的中间层拉平；超过 15 项且不是同型序列（如 `page-01…page-22`）时再按用途分组。目录深度一般不超过 4 层。
- **没有永久杂物桶。** 空目录删除；`tmp`、`misc`、`file`、`其他`、`新建文件夹` 这类目录要么清空，要么按真实内容改名（如 `review/paper-pages`）。用途不明的未定稿或中间变体放进所属主题下具名的 `drafts/`，不散落、不冒充成品。
- **代码与产物成对。** 保留语言和工具约定（包目录、`tests/`、`src/`）；脚本输出的位置和名称能对应到生成它的脚本，脚本内写死的输出／输入路径随迁移更新。

## 2. 命名

- **一个项目一种风格。** 先识别现有主导风格并统一到它；没有主导风格时，代码与数据项目用 `snake_case`，文档与网页项目用 `kebab-case`。字母一律小写，专有名词、基因名、方法名和数据集原名保留原写法（`MuCoST`、`Cbln3`）。
- **名字说明内容，由总到分。** `<主题>_<内容>[_<变体>]`，让同主题文件排序时自然聚在一起：`breast_reference_legend.png`、`breast_domains_numbered.png`。脚本用动词开头说明动作：`plot_breast_domains.py`，不用 `demo3.py`。
- **序号只表达顺序。** 只给有阅读或流程顺序的项目编号，同组零填充等宽（`01_`…`12_`）；无序内容不编号。
- **日期统一。** 全项目选 `YYYY-MM-DD` 或 `YYYYMMDD` 之一；只有按时间排序有意义时才把日期放在名字开头。
- **禁止噪声标记。** 空格、`(1)`、`副本`、`copy`、`final`、`最终`、`new`、`old`、`v2_final`、`untitled`、`test1` 一类名字不出现在整理后的树中；扩展名小写。版本只在多个版本都需保留时用 `v1`、`v2` 标出。
- **不改的名字。** 他人提供的原始数据（如竞赛给的 `summerOly_*.csv`）、冻结证据、外部工具或文档引用的文件、约定名（`README.md`、`__init__.py`、`LICENSE`）保持原名，在交付说明里列为有意例外。已有中文名不为统一而翻译，除非用户要求；新建名称按 SKILL.md 使用英文。

## 3. 冗余清理（已获删除授权时）

| 对象 | 处置 |
|---|---|
| 系统/编辑器残留：`Thumbs.db`、`desktop.ini`、`.DS_Store`、Office 已关闭后的 `~$*` | 直接删除 |
| 可再生缓存：`__pycache__`、`*.pyc`、`.pytest_cache`、`.ipynb_checkpoints` | 直接删除 |
| 完整哈希相同的副本 | 保留规范位置的一份，删除其余，并更新引用 |
| 被完整覆盖的旧版本 | 确认现行版包含其全部信息且无引用后删除 |
| 内容不同的变体、中间图、渲染页 | 生成脚本和输入仍在且无引用才可删；源文件已缺失（如原 PDF 不在而渲染页还在）时它们是唯一副本，保留并归位 |
| 空目录 | 从叶到根删除 |

“看起来多余”不是删除依据；名字、大小或日期相同也不是。

## 4. 执行与验收

1. 整理前运行 `python scripts/tidy_audit.py --tree <目标>`，记下发现项和原始目录树。
2. 写出目标树及“原路径 → 新路径／删除 | 理由”表，先查调用者（脚本中的路径、README、配置、文档链接），再按小批次执行。删除写成清单交给 `scripts/delete_paths.py`，不用 shell 删除命令。
3. 整理后再运行一次。目标是零发现；保留的每一项在交付说明中写明理由（例如原始数据名、约定名）。
4. README 里的目录说明必须与真实树一致；过期的目录说明本身就是缺陷。
5. 交付时给出整理后目录树、文件／目录／字节的前后数量、删除清单与理由、有意保留的例外。

自检：同级项目排序后是否形成有意义的分组；每个名字读出来是否就知道内容；是否还有必须打开才知道装了什么的目录。
