# 深度整理流程

## 1. 建立用途地图

优先读取既有 README、存储政策、项目配置和实验登记表；不读取密钥文件内容。盘点根目录每项：用途、状态、是否活跃、体积和依赖，再深入混杂部分。环境目录、Git 内部对象和应用管理库先识别边界，不递归扫描无关内部文件。

大目录先汇总文件数、子目录数、类型和大小；抽样只用于选择后续审阅路线，不作为深度完成依据。逐文件记录用途、处理状态和核对方式。拟删除或合并的文字报告全部阅读全文，代码检查依赖，二进制检查格式/结构及配套；元数据枚举、字节解码和内容语义审阅分别计数，不把自动读取冒称人工理解。只在去重或迁移校验需要时计算大文件哈希。将路径分为可处理、明确保护、外部依赖、待确认；待确认不是永久“杂项”分类。

临时操作表字段：`旧位置 | 用途/归属 | 采用状态及依据 | 保留/合并/移动/删除/待确认 | 新位置 | 信息覆盖及引用校验`。这是执行工具，默认不新增永久报告；若旧路径、来源身份或冻结记录需要它才能解释，保留必要映射，不能以清除过程文件为由删除。

实际修改前建立操作范围的全量基线：每个原文件、目录用途、链接及其对象均有去向；未处理项明确原位保留。先记录大小、内容校验及必要元数据，再执行。元数据包括对使用有意义的权限、时间、注释、扩展属性或数据流；目标格式/文件系统不能保真时保留源件并说明，不能宣称无损。秘密文件不读内容，也不写入清单；除非当前任务明确要求迁移它们，否则原位保护。

## 2. 选分类结构并深入落位

先辨明用户找文件时的主要问题，再选择分类轴：

| 情况 | 优先组织方式 | 不能打散的关系 |
|---|---|---|
| 多项目个人资料 | 项目或主题→用途 | 附件和正文、源稿和交付稿 |
| 单一代码项目 | 保留包与构建约定，整理外围数据与文档 | 导入路径、资源路径、环境配置 |
| 多模型实验 | 模型→数据集→协议/运行 | 相同运行的配置、权重、预测、指标 |
| 论文初稿与大修 | 阶段→实验问题→数据集/运行 | 图表、生成数据和对应结论 |
| 大型研究计划 | 沿用存储政策，区分实现、数据、持久报告 | 登记项、冻结协议、原始数值来源 |
| 资料交付或备份 | 可交付内容→必要源资料/校验 | 恢复路径、可编辑源稿 |

这是选择依据，不是要求每个项目创建所有层级。已有合理名称保持不变；用主题名解释内容，用稳定 ID 保留实验身份，日期只在区分版本有意义时出现。避免最终版2、new_final、同义目录、混合中英文缩写和没有边界的 misc。

根目录逐项归类并实际执行精简：标准接口保留，内容重叠的业务资料/产物归入已有主分类，临时生成物先看实物再清理。隐藏目录也纳入用途核查，但不遍历或移动Git内部、已安装环境和应用管理状态。不能把“旧路径曾被提到”当作所有根目录都不可调整的理由。

对每个混杂目录继续分组：源资料、采用成果、配套数据、实现、工作过程。既有完整运行包可以整体保留，不为视觉统一拆散其内部。若目录因活跃进程暂不移动，先让导航和状态可理解，不声称已经完成其物理归类。

## 3. 真正整合报告

1. 完整读取拟合并报告，包括附表、脚注、附件、注释和必要元数据；抽样只能用于盘点，不足以支持删除。不能解析或不能完整核对时保留源文件，只整合可验证部分。
2. 明确权威来源：数据和原始记录优先于口头总结；后续更正只有明确指向同一协议并提供依据时才替代旧结论，单凭日期不能决定。
3. 重复叙述写一次；互补信息按问题聚合；不同协议、结论冲突或尚未核验的差异单列并保留来源，不平均、不择优掩盖。
4. 一份主题汇总至少让读者看到：范围和现状、关键结论、可比结果、证据链接、必要限制或未完成项。没有数值不制造表格，简单任务不强行设置所有小节。
5. 总入口只解释目录职责与阅读顺序；主题汇总解释内容；原始日志保留不可替代细节。避免三层重复同一段结论。
6. 建立源段落/信息项→保留位置的临时覆盖表，逐项检查独有数值及精度、单位、条件、参数、限制、状态、失败信息、更正历史和来源。替代旧结论时保留“旧说法—更正依据—当前结论”的可追溯关系。删除须覆盖完整，而不只是保留主要结论；必要时保留精确摘录或原始文件，不强迫把全部原文塞进总览。
7. 多课题报告合并后，保留一份研究问题索引，列当前结论、关键数字、后续更正与唯一来源标识；避免长尾主题只剩无法理解的路径或哈希。不自动把原文开篇当作最终结论：未经归纳的摘录须标明来源和后续修订优先。
8. 来源完全被覆盖且无独有用途时，按既有授权删除或合并；原始证据、冻结记录、引用目标和独有参数不能因“已汇总”就删除。删前更新调用者并核对覆盖内容。哈希证明字节相同，不能单独证明不同文本的语义覆盖；独立复核不确定时保留源件。

可用的简表字段：`问题/研究 | 状态 | 主要结果及条件 | 证据位置`。状态采用项目已有术语，缺失写未核验，不编造统一成功状态。长路径放链接目标，显示标签简短明确。

## 4. 移动、修复、验证

先进行小批次移动并检查重命名引用，再扩展；跨卷先复制校验再按授权删源。路径重写要识别上下文，不对整个仓库盲目替换字符串；冻结文件或含内容哈希的清单不能静默改写。

读取验证现有脚本的用途与成本再运行，不为整理触发训练、联网下载或昂贵基准。集中保存原文时保留原始路径身份、精确字节和必要元信息，提供能实际读取/恢复的方法；先全量核对再删散件。选文字及二进制样本真实恢复并核对哈希和所保留的时间，冻结验证还应在恢复环境运行代表性历史检查，不能只因“存在容器”就称可复现。归档内部依赖、相对链接和文件存在性可静态检查；代码入口运行轻量检查。

配置中的相对路径按实际程序约定的基准解析（配置所在目录、工作目录或项目根），分别验证，不以 Markdown 链接检查代替数据/权重引用检查。重复运行整理应复用现有分类和汇总，不再生成第二套入口。

检查生成报告的脚本与模板，不只检查静态引用：一个旧变量可能同时读取数据、写入报告和过程日志。数据/报告分开归类时分别修复其读写根目录，不能只替换共同变量后把报告重新写进数据区，或重建已移走的顶层目录。不为验证路径修复执行联网搜索或训练。

代码退役须能说明：为何停用、当前调用检查结果、独有源码/参数/失败证据保留位置及恢复方法。调用关系分为当前维护接口、实际默认测试、历史重放、仅登记存在性；前两类需保持行为，后两类可通过来源记录/显式恢复承接。检查退役入口间的依赖闭包，不留下调用者或误删仍用的底层模块。不能因报告已汇总就直接删唯一实现。

区分持续维护工具和一次性迁移生成器；后者若重跑会覆盖后续维护成果，标明历史用途并在适用时增加明确停止条件，保留原逻辑而不将其误用为日常整理命令。只修改当前迁移直接影响的脚本。

冻结原文与当前可读副本分开验证：前者保留字节、原始路径基准及哈希；后者修复导航。仅在确有冻结要求时保留必要原文副本，并在现有入口写清用途和旧链接的解析方法，不堆积无理由备份。对历史原文的旧链接单独归类，不能把它们混成当前导航故障，也不能用“历史文件”豁免真实信息缺失。


## 清理故障处理

执行删除前把目标限定到已核验清单。空目录从叶到根逐个处理：确认绝对路径在授权范围内、不是联接或符号链接，使用包含隐藏项且遇错即停止的枚举检查为空；使用非递归、明确 LiteralPath 的原生命令，删除后核对不存在。不存在视为已完成；出现新内容立即退出并重新审阅，不自动升级为递归删除。路径检查与空检查不保证没有并发写入，工具出现非空提示时必须停止。

根据实际返回选择处理，不将所有失败笼统称为权限问题：

| 返回情况 | 处理 | 停止条件 |
|---|---|---|
| 工具执行前 `blocked by policy`／审批拒绝 | 记录原始返回及目标；没有原因就明确原因未知。仅当能实质降低操作范围或风险时尝试更窄方案，例如从批量递归改为一个已核验空目录的非递归删除 | 更窄方案仍拒绝，或已明确禁止该动作，停止该动作；不换 shell、编码、语言、API、代理或移动目标来规避，不关闭审批或改权限配置 |
| 已执行后 Access denied／权限不足 | 只读检查路径、属性和权限，排除链接及受保护位置；向用户说明具体系统错误 | 不擅自取得所有权、改 ACL 或提权；缺少相应授权则保留 |
| 文件占用／共享冲突 | 查可确认的占用进程或任务状态，保留活跃训练和下载 | 不强制终止进程；只有占用已解除的证据时才重试 |
| 非空／哈希变化／文件消失 | 刷新该项状态；消失则核对保留来源，新增或变动内容重新审阅 | 不扩大通配范围，不覆盖新内容 |

Codex 返回策略拒绝时，先做只读诊断，再给具体恢复路径：

1. 分别核对会话实际 `approval_policy`、`sandbox_mode`、`approvals_reviewer` 与配置文件；会话可能覆盖用户配置，Full Access 也不能用来证明某条命令获准。
2. 用官方 `codex execpolicy check --pretty --rules <规则文件> -- <原命令及参数>` 检查可访问规则的匹配，不执行目标命令。检查相关用户、受信项目和受管规则；只查了部分规则时明确范围。`matchedRules: []` 只说明所查规则无匹配，不证明平台会放行。
3. 若证据表明动作要求审批而会话为 `never`，说明可由用户在界面切换到支持审批的模式，并在需要时选择人工审批后重新提交该动作。`on-request` 是官方交互式审批策略；它不覆盖 `forbidden` 或受管禁令。skill 不自行改审批配置，也不承诺切换一定修复未知来源拒绝。
4. 若明确命中 `forbidden`，按规则说明处理或联系管理者；若没有匹配原因，保留最小复现、版本、错误原文和已检查范围，使用产品反馈渠道。不要靠添加宽泛 allow 规则或关闭沙箱解决未知拒绝。

依据：[OpenAI 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)、[命令规则与只读检查](https://learn.chatgpt.com/docs/agent-configuration/rules)。诊断命令以本地版本 `--help` 为准。

失败后继续可独立完成的整理与验证，不反复重试同一动作。命令尚未执行的拒绝不能作为系统 ACL、文件占用或命令语法错误的证据。未获原因时不得声称已找到平台根因。

最终分别报告已删文件、已删空目录和剩余项；不要留下“全部完成”与仍存在的候选目录相矛盾。现有入口仅保留影响使用的缺口；审批过程留在对话或既有任务记录，不为几处空目录新增永久故障报告。skill 能改进操作和判定，不能承诺解除工具层审批。

## 5. 科学、工整、明了的验收

- **分类完整**：所有范围内一级项都有解释；选中的混杂目录内部已分类，未用一个大箱子掩盖混乱。
- **命名有序**：同层分类不重复不交叉，名称能说明内容，层级与文件量相称，没有空目录和无意义编号。
- **内容汇总**：业务结论已整合，重复减少，差异和来源保留；不是只做文件搬运或链接堆积。
- **信息不丢失**：全部处理项都有去向，原样迁移哈希一致；内容合并逐项核对覆盖，原始证据和必要元数据可获取。尚未完成核对的源文件保留，不能只凭文件数相等或摘要看似完整判定无损。
- **可追溯**：结果能定位到正确输入、参数和输出；路径、引用和协议核对通过。
- **易读美观**：查看真实目录树与渲染后的 Markdown（无渲染工具时检查阅读顺序与链接）；表格不过宽、链接标签清晰、入口不堆满过程记录。无需给目录截图装饰。
- **数量确实减少**：报告、子目录与根目录一级项的前后数量可核对；旧报告已按授权删除，没有因新增汇总、收据或备份制造更多重复。未减少的运行/数据组有依赖或独立身份依据。只完成报告专项时，不声称整项目都已逐文件语义审阅。
- **便于交接**：不熟悉项目的 agent 能从入口完成代表性的检索任务；未完成项准确标明，重复执行不会再次产生一套汇总或重复目录。

多代理交接只提供：范围、排除项、权威来源、选定分类轴、路径映射、已验证项和未决项。跨代理共享索引指定一个写入者；审查者以具体路径和失败项反馈。
